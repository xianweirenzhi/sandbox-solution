# F8266-2：ESP8266（Adafruit HUZZAH）WiFi 联网模块项目

> 本文档由 Claude Code 维护，随项目变更同步更新。最后更新：2026-09-09

## 项目概述

基于 PlatformIO + Arduino 的 ESP8266（Adafruit HUZZAH ESP8266，4MB Flash）测试项目。**本项目由 [F8266-1](../F8266-1/) 于 2026-09-08 克隆而来**，骨架与 F8266-1 同构（传感 + 执行 + OLED + 主机链路），但**定位与智慧农场（F8266-1）不同，已做差异化**：**不含 MQ-2 可燃气体传感**；原 SHT30 温湿度 + GY-30 光照两个传感器合并为 **GY-39 气象二合一模块**（温湿度 + 气压 + 光照，**直连芯片 / UART / I2C 三模式自适应**）；土壤湿度改用 **AO 模拟量**（经分压接唯一 ADC 引脚 A0）；其余差异为设备身份 `F8266-2`、主机端口 8001、构建环境名。**当前状态：编译通过，待上板联调**（硬件按本文接线表逐步接回，未接的传感器会显示故障并热插拔自愈，不影响运行）。

当前固件以 **WiFiManager 驱动 STA 模式**联网：

- 开机直连硬编码默认网络 `ESP-TEST` / `88888888`；
- 默认网络不可达时，自动打开**同名配置热点** `F8266-2`（192.168.4.1），供手机/电脑改配无线参数；
- 设备 STA 主机名固定为 `F8266-2`，在路由器客户端列表 / 局域网内以此名出现；
- 联网后作为 TCP 客户端连主机 [esp32-1](../esp32-1/)（端口 8001），连上即上报上线，并收发 `@命令/` 帧；
- **主机动态发现**：主机的 IP 可能由 DHCP 动态分配，从机监听主机在局域网 UDP 端口 `45555` 的广播宣告（`ESP32HOST,<ip>,...`）自动获知主机当前 IP，无需写死；主机 IP 变化会自动跟随，超过 20s 未收到宣告则回退到 `net_config.h` 的硬编码地址。

**业务定位（沙盘第二节点·差异化）**：沙盘子系统的**状态节点**，接入传感子系统① GY-39 气象二合一（温度/湿度/气压/光照，直连芯片/UART/I2C 三模式自适应，替代 SHT30+GY-30 两点）、② 土壤湿度（**AO 模拟量**经分压→A0，中值滤波 + 滞回阈值判定）、③ SGP30 空气质量（eCO₂/TVOC）+ 执行实体（水泵/风扇/舵机）——**不含 MQ-2**（本项目定位与智慧农场不同）；读数/故障/执行器状态实时上屏（信息区 6 行，当前使用 5 行）并周期上报主机。

**命名约定**：设备身份、STA 主机名、配置热点名统一使用 `F8266-2`，与项目目录同名。该身份对应仓库 [esp32-1](../esp32-1/) 主机 6 路 TCP 从机端口中的 `F8266-x` 命名体系——**F8266-2 接入主机 8001 端口**（一从机一端口）。主机 IP 默认支持**动态发现**（监听主机 UDP 广播）；回退地址 `192.168.1.100` 仅在网络中无主机宣告时兜底（改主机 IP / 端口 / 广播参数只动 [net_config.h](src/net_config.h)，须保证与从机同一网段）。命令词表已定义（`PUMP`/`FAN`/`SERVO`，见第 5/12 项），`onHostCommand()` 已解析执行，未知命令仅串口打印。

**克隆差异说明（相对 F8266-1）**：

| 项 | F8266-1 | F8266-2 |
| --- | --- | --- |
| 设备身份（STA 主机名 / 配置热点名 / 上线帧 / OLED 标题） | `F8266-1`（`NET_DEVICE_NAME`） | `F8266-2`（`NET_DEVICE_NAME`，其余代码自动跟随） |
| 主机监听端口 `NET_HOST_PORT` | 8000 | **8001** |
| 构建环境名（platformio.ini） | `esp01_1m`（历史沿用） | `f8266_2` |
| MQ-2 可燃气体传感 | 有（子系统③，仅本机使用不上报） | **无**（定位不同，模块已删除，A0 让给土壤 AO） |
| 温湿度 + 光照 | SHT30（I2C 0x44）+ GY-30/BH1750（I2C 0x23）两个传感器 | **GY-39 气象二合一（直连芯片 / UART / I2C 三模式自适应）**：BME280 温/湿/气压 + MAX44009 光照，一个模块四项读数（上报新增 `press` 气压字段，其余字段名不变） |
| 土壤湿度传感器 | DO 数字量→GPIO14（1s 环境消抖） | **AO 模拟量经分压→A0**（中值滤波 + 滞回双阈值判定，上报仍为 0/1 湿干两态，主机协议不变） |
| MAC 地址 | — | **无需修改**：ESP8266 MAC 出厂每片唯一，固件未硬编码任何 MAC，克隆不产生冲突 |

本项目位于仓库 [sandbox-solution](https://github.com/xianweirenzhi/sandbox-solution)（公开）的 `F8266-2/` 子目录——仓库为多板卡项目集合，其他板卡项目以同级目录存放，详见仓库根 [README](../README.md)。

**外设接线**（多数与 F8266-1 同款；温湿度+光照合并为 GY-39、土壤改 AO 模拟量、无 MQ-2，按此逐步接回）：

| 外设 | 接口 | 接线 |
| --- | --- | --- |
| OLED 0.96"（SSD1306） | I2C | SDA→板上 SDA（GPIO4）、SCL→板上 SCL（GPIO5）、VCC→3V3、GND→GND；I2C 地址 0x3C |
| GY-39 气象二合一（BME280 温湿度气压 + MAX44009 光照） | I2C 直连芯片（★实测推荐）/ UART / I2C-MCU | VCC→3V3、GND→GND；**接法三选一，固件自适应**：① **直连芯片（板边 SDA/SCL 焊盘，绕过模块 MCU）**：模块 **SDA→板上 SDA（GPIO4）、SCL→板上 SCL（GPIO5）**，BME280@0x76 + MAX44009@0x4A 直接上总线（实测即此模式）；② UART（出厂默认，免焊）：**CT→GPIO14**（板上标 14 的排针），DR 不接，9600bps 主动发帧；③ I2C-MCU：S0 焊桥接 GND 后 **CT→SCL、DR→SDA**，地址 0x5B |
| 土壤湿度传感器 | ADC（A0） | VCC→开发板 3V3、GND→GND；**AO──[5×1kΩ 串联]──┬──[1kΩ]──GND（5:1 分压），分压点接 A0**（模块 AO 满摆幅约 3.3V，HUZZAH ADC 量程仅 0~1V，**直连超量程会贴顶并可能损伤 ADC**；分压后 3.3V→0.55V）；DO 悬空（GPIO14 不再使用） |
| SGP30 空气质量（eCO₂/TVOC） | I2C（与 OLED 共线） | SDA/SCL 并接到同一总线、VIN→3V3、GND→GND；I2C 地址 0x58（固定，无地址选择脚） |
| 水泵（高触发继电器/MOS） | GPIO 输出 | 驱动模块 IN→**GPIO0**（高=开泵）；GPIO0 烧录时拉低=泵关（安全），上电瞬间内部上拉=高会短暂开启几十 ms（电机响应慢通常无感）；模块 VCC/GND 按模块接 3V3/GND；**泵体电源独立供电 + 共地** |
| 风扇（双路低触发，正反转） | GPIO 输出 ×2 | 驱动模块 IN1(正转)→**GPIO13**、IN2(反转)→**GPIO2**；**★两路严禁同时触发**（电源直通短路），固件已软件互锁；风扇电源独立 + 共地 |
| 舵机（180° 摆角，SG90 类） | GPIO PWM | 信号线(橙)→**GPIO12**、VCC(红)→独立 5V、GND(褐)→共地 |

## 当前功能

代码按职责拆分到独立模块，`main.cpp` 仅做编排（详见"目录结构"），模块化约定与 F8266-1 一致：

1. **默认网络直连（STA）**：开机以 STA 模式直连 `ESP-TEST`（密码 `88888888`），最多等待 12s；成功后打印 IP 并进入主循环。
2. **同名配置热点兜底**：默认网络连不上时自动开启配置热点 `F8266-2`（WiFiManager），手机连接后访问 <http://192.168.4.1> 可改配其他无线网络；热点最长停留 180s，超时无人配置则自动重启重试。
3. **断线自愈**：运行期失联超过 15s（SDK 自动重连未恢复）自动重连默认网络 / 重新开配置热点。
4. **串口日志**：串口打印联网全过程（SSID / IP / hostname / 各阶段状态），便于排障。
5. **主机 TCP 链路**：联网后自动作为 TCP 客户端连主机 `:8001`，连上即发上线帧 `@F8266-2 online/`（主机网页对应端口变绿）；在线期间接收主机 `@…/` 命令帧并回调 `onHostCommand()` 解析执行执行器命令（`PUMP ON/OFF`、`FAN FWD/REV/STOP`、`SERVO 0~180`），未知命令仅串口打印；主机离线自动按重试间隔重连，重连成功重新上报上线；WiFi 掉线期间链路自动暂停，恢复后重连。
6. **主机动态发现**：`host_link` 监听主机 UDP 广播（端口 `45555`），收到 `ESP32HOST,<ip>,...` 宣告即把目标主机切到该 IP（连旧地址则断开重连）；超过 `NET_HOST_DISCOVER_STALE_MS`（20s）无宣告则回退 `NET_HOST_IP`。主机为 DHCP 动态 IP 时从机仍能自动找到它。
7. **OLED 状态屏（状态可视化层）**：0.96" SSD1306（I2C：SDA=GPIO4、SCL=GPIO5，地址 0x3C）开机即点亮，标题行（设备名 + SmartFarm 合并一行）；下方**信息区 6 行**（当前使用 5 行）由各子系统经 `setInfoLine(row, ...)` 写入状态文本（每子系统一行，通用接口，行内容变化才重绘）（文字统一 ASCII/英文，暂不引入中文字库）。
8. **GY-39 气象二合一采集（子系统①，直连芯片 / UART / I2C 三模式自适应）**：板载 BME280（温度/湿度/气压）+ MAX44009（光照），一个模块四项读数，替代原 SHT30+GY-30 两点；**固件开机与重扫时并行探测三路，哪边先上线用哪边，接线热切换自愈**——① **直连芯片（★实测采用）**：模块板边 SDA/SCL 焊盘直连板上 I2C（绕过模块 MCU），BME280（0x76/0x77 双地址探测，Adafruit 库含出厂校准补偿）每 2s 读温/湿/气压 + MAX44009（0x4A）读光照（0x03/0x04 寄存器，lux=M·2^E·0.045，默认连续模式免配置），双芯片均消失自动回探测（热插拔）；② **UART（出厂默认模式，免焊）**：SoftwareSerial 9600bps 只收（GPIO14，`PERIPH_GY39_UART_RX`），解析官方帧协议 `5A 5A <type> <len> <data[len]> <累加和校验>`（0x15=光照 4B / 0x45=T2+P4+H2+海拔2，大端 /100），帧流停 30s 降级回探测；③ **I2C-MCU 0x5B**（S0 焊桥接 GND 后 CT=SCL、DR=SDA）：每 2s 直读数据寄存器（0x00~0x0D 共 14 字节大端），读事务三样式自适应（repeated start / STOP 再读 / 直读）+ 时钟拉伸上限放宽 3ms；**健康判定**——连续 3 次失败或读数超物理范围（T -40~85℃ / H 0~100% / P 300~1200hPa / lux 0~200k）标记故障（OLED 显示 `GY39 ERR`），恢复自动转好；光照与温湿压**独立跟踪有效性**（任一缺失对应字段上报 null / OLED 显 `--`，互不拖累）；上电未检测到不阻塞启动，每 10s 重扫；**开机探测失败时自动全总线扫描并打印应答设备地址**（0x3C OLED/0x58 SGP30/0x5B MCU/0x4A+0x76~77=直连芯片）；读数/故障每秒上屏（行 0 `T:25.3C H:56%`、行 1 `L:1234lux P:1013h`），串口同步打印。
9. **土壤湿度监测（子系统②，模拟量）**：模块 AO（3V3 供电，满摆幅约 3.3V）经 **5×1kΩ/1kΩ 分压（5:1）**接唯一 ADC 引脚 A0（分压后 3.3V→0.55V≈560 counts，防超量程），每 1s 采集（单周期 5 采样中值滤波，抑制 ESP8266 ADC 的 WiFi 干扰抖动）；判定语义 **低电压=湿润适宜、高电压=过干**（与 F8266-1 数字模块 DO 高=干 极性一致）；**滞回双阈值防抖**——滤波值低于 `SOIL_MOIST_BELOW`(300) 才判湿、高于 `SOIL_DRY_ABOVE`(420) 才判干，两阈值之间维持原判定，临界湿度附近的缓慢漂移不会引起状态翻转（★两阈值为 5:1 分压估算默认值，**须现场标定后按需调整**，标定依据 OLED 行 2 显示的滤波原始值 `SOIL:WET 256`）；开机按首采滤波值给初始判定（不误报）；**贴顶提醒**——连续 10s 贴满量程（≥1015）串口提示疑似 AO 直连未分压/接线异常；串口同步打印判定切换与原始值。
10. **SGP30 空气质量采集（子系统③）**：I2C 0x58 共线，每 2s 读 **eCO₂(ppm) + TVOC(ppb)**；★**eCO₂ 为 TVOC 推算的等效值**（非真实 CO₂ 浓度，酒精/VOC 会使其虚高，作空气新鲜度参考；后续从机需真 CO₂ 应选 SCD40 等），未做基线持久化（重启后重新积累，约 12h 达最优精度）；**15s 暖机**——上电/重扫后暖机期内读数不可靠且失败不判故障（OLED 显示 `SGP30 INIT`）；健康判定/热插拔重扫同子系统①；OLED 行 3 显示 `C:800ppm V:12ppb` / `SGP30 ERR`，串口同步打印。
11. **执行实体（水泵/风扇/舵机，首个执行层）**：`actuator_ctrl` 模块，控制入口已接主机命令词表（见第 12 项）；★**业务语义：舵机=大棚——0°=关棚 / 180°=开棚，安全位取 0°(关棚)**；**上电安全态**——泵关（GPIO0 低）、风扇停（GPIO13/2 双高）、舵机回 0° 关棚（GPIO12，Servo 库 50Hz）；**触发极性**——水泵**高触发**（高=开，GPIO0 烧录拉低=关，安全）、风扇双路**低触发**（低=开）+ 正反转**软件互锁**（开任一路前强制断开另一路，杜绝两路同触导致驱动级电源直通短路）；**上电自检**——初始化完成后逐个激活执行器 0.5s（泵开→扇正转→扇反转→舵机摆 180°(开棚演示)→回 0°关棚）供人工检查接线/动作；**断连保护**——与主机连接断开（TCP 断/WiFi 断）即 `allStop()` 全停（泵关+风扇停+舵机 0°关棚），重连后不自动恢复（需主机重新下发命令）；**重连补报**——重连成功立即补发一次设备状态（传感+执行器实时态），让主机网页快速同步（断线期间执行器已全停，主机旧显示可能不符）；舵机 `servoSet(0~180°)` 自动夹取；OLED 行 4 显示 `P:OFF F:OFF S:0`(关棚) 实时反映执行器状态，全部动作串口打印。
12. **数据上报 + 远程控制**：每 2s（`NET_REPORT_MS`）打包传感数据 + **执行器实时状态**为 JSON 帧上报主机——温湿度/气压（hPa，GY-39 新增字段，主机端暂不解析不冲突）/光照/土壤（0/1 湿干两态，由滞回阈值判定）/eCO₂/TVOC，无数据字段填 `null`；并含 `pump`(0/1)、`fan`(0停/1正转/2反转)、`servo`(0~180°) 三字段，主机网页执行器卡据此实时显示当前态（`@{"t":25.3,"h":56.0,"press":1013,"lux":1234,"soil":1,"co2":800,"tvoc":12,"pump":0,"fan":1,"servo":0}/`，0=关棚 180=开棚）；接收主机下发命令并执行——`PUMP ON/OFF`、`FAN FWD/REV/STOP`、`SERVO 0~180`（`onHostCommand()` 内解析，未知命令仅打印）；帧长上限 `NET_FRAME_MAX_LEN`（128 字符）。

> 说明：凭据为硬编码默认值，重启后始终优先尝试 `ESP-TEST`；配置热点仅作断网/改网兜底入口。无线参数与主机连接参数集中在 [src/net_config.h](src/net_config.h) 一处修改。

## 使用方法

```bash
pio run -d F8266-2              # 编译（在仓库根执行）
pio run -d F8266-2 -t upload    # 烧录到开发板
pio device monitor              # 打开串口监视器（115200）
```

VSCode 中直接打开 `F8266-2` 文件夹即可用 PlatformIO IDE 的构建/烧录按钮。

**预期现象**：烧录上电后，OLED 即点亮标题行（`F8266-2 SmartFarm`）——未接外设时各传感行显示对应 `ERR`（每 10s 自动重扫，接上即恢复），土壤行（模拟量，无在线探测）显示当前判定 + 原始值，执行器自检无负载则仅串口打印动作。完整现象（含各传感器读数与执行器动作）与 F8266-1 基本一致（差异：GY-39 占行 0/1 两行、无 MQ-2 行、土壤为模拟量），见 [F8266-1 README「预期现象」](../F8266-1/README.md)。联网后若主机 esp32-1 在线，串口打印「上报上线」，主机网页 **8001** 端口卡变绿显示「**F8266-2 已上线**」（主机与从机须在同一局域网网段，且 `NET_HOST_ANNOUNCE_PORT` 与主机 `HOST_ANNOUNCE_PORT` 一致）。

## 模块扩展指引

后期新增功能（如 LED/继电器控制、由主机命令驱动的具体业务）时，请遵循**解耦约定**：

1. 每个功能一个模块文件（如 `led_ctrl.h/.cpp`），只暴露少量接口方法；
2. 在 `main.cpp` 顶部实例化，并在 `loop()` 的"业务模块扩展位"调用其 handle；
3. 模块内第三方库 include 只写在 `.cpp`，头文件不泄漏实现细节；
4. 网络 / 主机参数 / 外设引脚变化只改 `net_config.h`，业务代码不感知。

与主机通信的约定：主机下发命令（PUMP/FAN/SERVO）在 `main.cpp` 的 `onHostCommand()` 回调中解析执行；从机周期上报传感数据用 `link.send(json)`（`host_link` 自动包成 `@json/` 帧，已自动剥离帧头尾；帧内容勿含 `@` / `/`，单帧上限见 `net_config.h` 的 `NET_FRAME_MAX_LEN`，现为 128 字符）。
